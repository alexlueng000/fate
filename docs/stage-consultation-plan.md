## 回复与上下文协议

- 继续使用 SSE 正文协议，兼容历史 Markdown；仅首次完整解读使用 `### 核心观察`、`### 分析依据`、`### 现实建议`。
- 追问直接作答；信息不足先澄清，不强制填满各节。
- 推荐问题保留已有标记协议；不存在有效推荐时不强行填充跨主题问题。
- 命盘/卦象只来自程序计算。用户输入和检索片段是数据，不作为系统指令。
- task_context 保存用户明确输入的问题、背景、选项、期限；模型建议不得混入用户事实。
- 原始消息仍为事实来源；展示摘要不自动充当长期记忆。

## 单问题权益规则（本地实现默认，发布前可配置）

- 新商品以配置标识为问题解读，价格来自商品表；不修改已有商品价格。
- 权益绑定用户和单一会话；八字/六爻各自使用会话，不因客户端传参跨会话使用。
- 期限与成功回复上限来自商品配置，并在购买时快照；界面在购买前明确展示。
- 期限从支付成功时开始，避免首次请求并发导致激活歧义。
- 支付通知幂等授予。只有服务端已确认支付的订单可获得权益。
- 生成失败不计成功回复；请求期间预留名额，阻止并发超额；重试有请求标识。
- 到期可查看历史；新权益可续问。旧次数保留，只有用户明确选择旧配额方式才消耗，不能静默双扣。
- 退款成功撤销该订单权益，不影响其他订单与旧配额；重复回调不重复处理。
- 本地测试以隔离数据库/替代支付提供方验证，不调用真实支付或改动线上配置。

## 验证与迁移

- 增量建表，不删除旧表/字段；新增规则与商品通过显式脚本配置。
- 自动化覆盖协议解析、场景路由、事实保留、知识库失效、跨用户访问、权益边界、重复通知、并发与退款。
- UI 使用本地演示模式验证，不将演示账号或伪造支付成功入口带入正常运行模式。
- 真模型/支付/数据库服务缺失时明确记录未验证项，不把 mock 验证写成线上验收。


## 实现位置与组件取舍

- M1：前端 `app/components/consultation/`、`app/consultation.css`、原 MessageList/InputArea。沿用奶油底色、朱砂强调、衬线标题。采用 Radix Accordion/Dialog（shadcn 常用的基础能力），保留既有输入和 Markdown；未引入多个完整 UI 库。
- M2：`/career` 三步引导 → `/panel` 或 `/liuyao`；档案跳转保留问题；命盘/背景抽屉内记录行动复盘；历史页进入单问题解读。
- M3：后端 `app/chat/consultation.py`、RAG 类型隔离与来源 hash、原问题和最近十条消息、六爻六爻明细、数据库 Prompt seed；中文 TF-IDF fallback 使用字符 n-gram。8 个固定语义评测案例及离线结构检查器见 `evals/` 和 `scripts/evaluate_consultation.py`。
- M4：前端 `/reading/[id]`、后端 `/api/consultations/*`、独立权益与请求表、复用微信 Native/JSAPI。失败、半截流、退款不计成功回复；服务端落库后才发送完成标志。重复请求回放；网络不确定时复用请求编号；旧配额入口明确分开。

## 本地验证结果（2026-10-02）

- 前端 Node 回归：63 项通过（原基线 59 项），含 SSE 错误、截断、可选追问。
- 后端：142 项及 6 个子测试通过，涵盖排盘、上下文、RAG、API、权益、退款和原有支付回归。
- 浏览器：桌面 1440px、手机 390px，共 6 项；三步流程、必要信息、抽屉、完整固定回复、中文输入法、付费追问、依据折叠、刷新恢复、额度耗尽、购买前规则、旧配额入口。付费接口使用浏览器替代数据，不是实际扣款。
- TypeScript、变更文件 ESLint、Next.js production build 通过；已检查手机页面截图。
- 本地已重建八字 14 分片、六爻 16 分片索引。生成索引忽略提交，由脚本复建。
- 后端测试使用独立 SQLite/替代提供方，数据库连接配置指向不可用的本机测试端口，未读写线上数据。
