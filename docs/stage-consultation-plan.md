## 完整报告增量（2026-10-02，继续优化阶段）

- `GET /api/conversations/{id}/report` 从已保存消息读取最早的完整章节解读；后续追问不会取代初始报告。支持事业三个章节及个人报告七个章节，不调用模型补写旧内容。无完整章节返回 409，仍允许查看原对话。
- 复用会话所有权检查和八字命盘快照。报告带原问题、明确填写的背景、生成时间、源消息编号与原文。没有记录的背景明确提示缺失，不从 AI 回复反推用户事实。
- `/reports/[id]` 提供独立阅读、章节目录、默认收起的分析依据、完整原文、背景/命盘/卦象、相关追问及复盘。历史记录与已保存的结构化回复提供入口；追问进入原会话并先填入可编辑草稿。
- 八字续聊读取数据库的原始任务背景，已绑定后不会被其他浏览器的陈旧任务覆盖。八字流式生成要求上游完成标志；问题与完整回复同一事务提交，保存失败或生成中断不发送成功完成标志，不向对话记忆写入失败的半截回复。
- 本次报告 HTTP 回归使用文件 SQLite，并重新创建数据库引擎验证恢复；浏览器报告回归使用接口替代数据。它们不证明真实模型内容或线上 MySQL 已验收。
- 当前本地回归：前端 63 项 Node 测试、桌面/手机 14 项浏览器测试、后端 153 项及 6 个子测试通过；生产构建通过。变更文件 ESLint 无错误，旧 `/chat` 页保留一条既有 Hook 依赖警告。

## 回复与上下文协议

- 继续使用 SSE 正文协议，兼容历史 Markdown；仅首次完整解读使用 `### 核心观察`、`### 分析依据`、`### 现实建议`。
- 追问直接作答；信息不足先澄清，不强制填满各节。
- 推荐问题保留已有标记协议；不存在有效推荐时不强行填充跨主题问题。
- 命盘/卦象只来自程序计算。用户输入和检索片段是数据，不作为系统指令。
- task_context 保存用户明确输入的问题、背景、选项、期限；模型建议不得混入用户事实。
- 原始消息仍为事实来源；展示摘要不自动充当长期记忆。

## 单问题权益规则（本地实现默认，发布前可配置）

- 新商品以配置标识为问题解读，价格来自商品表；不修改已有商品价格。
- 权益绑定用户和单一会话；八字/六爻各自使用会话，不因客户端传参跨会话使用。
- 期限与成功回复上限来自商品配置，并在购买时快照；界面在购买前明确展示。
- 期限从支付成功时开始，避免首次请求并发导致激活歧义。
- 支付通知幂等授予。只有服务端已确认支付的订单可获得权益。
- 生成失败不计成功回复；请求期间预留名额，阻止并发超额；重试有请求标识。
- 到期可查看历史；新权益可续问。旧次数保留，只有用户明确选择旧配额方式才消耗，不能静默双扣。
- 退款成功撤销该订单权益，不影响其他订单与旧配额；重复回调不重复处理。
- 本地测试以隔离数据库/替代支付提供方验证，不调用真实支付或改动线上配置。

- M3：后端 `app/chat/consultation.py`、RAG 类型隔离与来源 hash、原问题和最近十条消息、六爻六爻明细、数据库 Prompt seed；中文 TF-IDF fallback 使用字符 n-gram。8 个固定语义评测案例及离线结构检查器见 `evals/` 和 `scripts/evaluate_consultation.py`。
