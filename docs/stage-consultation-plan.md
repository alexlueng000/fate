- `/reports/[id]` 提供独立阅读、章节目录、默认收起的分析依据、完整原文、背景/命盘/卦象、相关追问及复盘。历史记录与已保存的结构化回复提供入口；追问进入原会话并先填入可编辑草稿。

## 完整回复、个人报告与柔和界面增量（2026-10-03）

- 八字/六爻普通回复统一使用 `save_completed_exchange`：核实会话归属/类型，完整问题和回复、一次旧配额、个人报告缓存（适用时）同事务提交；提交后才发送完成标志。生成截断、空回复、保存失败和剩余额度竞争失败均不保存半截回复、不新增扣次。
- 普通 SSE 默认要求完成标志，提交时的 429 仍可被前端识别为额度耗尽。一次性模型回复也必须确认 `finish_reason=stop`。数据库已提交而缓存失败时，回复仍成功；后续可从数据库恢复。
- 配额周期重置在行锁下重新读取，避免过期的页面查询覆盖刚完成的次数；生成期间不持有配额锁。本地文件 SQLite 验证了回滚、最后一次竞争及陈旧周期查询，真实 MySQL 行锁效果仍未验证。

## 重新解读与空白会话增量（2026-10-03）

- 八字/六爻重新解读直接读取所属数据库会话与原命盘/卦象，工作进程缓存消失后仍可执行。仅完整生成且事务提交成功后追加新回答和消息编号；原回答、评价及初始报告保留，后续提问使用最新回答。延续原免费重新解读规则，不另扣旧次数。
- 生成前核对目标消息编号，保存时在会话锁下重新核对最后一条回复；若已有另一回答或新问题，则返回 409，避免追加到错误轮次。跨账号、八字/六爻类型混用，以及六爻 URL 与会话卦象不一致均拒绝。
- 清空入口校验所属用户，创建保留原命盘快照的空白会话，去除原任务背景；原会话/报告留在历史。事务失败不会删除旧内容。具有命盘快照但尚未关联个人档案的已保存会话也可恢复。
- 前端收到新会话编号和欢迎语后一起切换状态，避免旧消息误缓存到新编号；发送认证头，清空前说明历史保留。重新解读追加新回答并标明原回答保留，失败可重试。历史八字页在最后一条回答下提供明确操作入口。
- 23 项新增后端隔离测试覆盖重启恢复、失败回滚、目标过期、所有权、旧评价/报告保留、空白上下文及可理解的失败信息；6 项新增桌面/手机浏览器检查覆盖原文保留、从接口重载、失败重试及清空缓存一致性。MySQL 锁与真实模型效果仍需测试环境验证。

## 首次个人报告生成保护（2026-10-03）

- `/report` 使用 `POST /api/chat/start` 的 `personal_report: true` 模式；该模式仅使用登录用户当前档案，不接受游客分析或事业任务混入。普通开场接口保持兼容。
- 新增 `personal_report_requests` 表，以档案为唯一生成记录，保存命盘 hash、请求 token、会话编号和十分钟预约期限。短事务统一按配额、档案、请求行顺序加锁，模型调用期间释放锁。同一命盘的在途请求返回 409；已经完成的报告即使无剩余次数也可直接回放，不再次调用模型。
- 完整回复保存时校验当前命盘、预约 token、用户及会话编号；报告、消息、一次旧配额与请求成功状态一起提交。失败或连接结束仅释放该 token 的在途预约；进程异常退出由期限允许恢复。被接替的旧请求不能追加报告或扣次。
- `GET /api/chat/report/status` 只返回当前登录用户的状态和已保存报告。另一个页面遇到在途请求时每两秒查询状态，最长十分钟；断流后也先查询已保存结果。自动恢复只查询，不发第二次模型请求。失败后仍可手动重新加载，重新加载先查档案。
- 修正旧 Markdown 处理将规范章节标题后的短正文误合并进标题的问题，支持没有空白行的合法章节格式，不改变其他标题修复逻辑。
- 18 项新增后端隔离测试覆盖四请求竞争、重复完成、零额度回放、失败/过期重试、旧 token 拒绝、命盘更换、原子回滚、状态归属和主动断连。4 项新增桌面/手机浏览器检查验证等候既有请求及提交后断流恢复。全组后端 227 项通过后，新增断连专项测试也通过；不代表真实 MySQL 并发已验收。
- 测试环境部署前必须先应用 `scripts/2026-10-03_personal_report_requests.sql`。其外键按仓库定义的 `user_profiles.id`（INT UNSIGNED）和 `conversations.id`（INT）设计，执行前核对测试库实际类型及 InnoDB；已有表与旧报告不做破坏性修改。缺表返回可重试错误，不静默降级为无幂等保护的生成。

## 六爻失败恢复与会话归属（2026-10-03）

- 普通追问失败时继续显示已有解读，移除未确认保存的临时问题与半截回复，保留原问题草稿；快捷分析保留完整问题内容。草稿在当前账号/会话的 sessionStorage 中保存，刷新后仍可编辑。
- 恢复操作读取所属数据库会话，不重新生成上一条回答。只有保存的消息编号、原问题及对应完整回答均匹配时，才认定断流请求已完成；用户编辑的新草稿不会因恢复旧回答而丢失。
- 首次解读明确服务端失败时允许手动重新开始；连接结果不明时保留会话编号，先检查保存记录。开始、追问、快捷分析和重新解读使用同一页面操作锁，停止按钮接入取消信号；生成期间禁用重新起卦。
- 普通追问与快捷分析在检查配额及调用模型前，校验 URL 卦象与所属会话一致；另一卦象、不同类型或不存在的会话返回 404。
- 此轮发现普通追问及六爻首次解读缺少服务端请求编号/在途预约，读取当前历史不能证明另一个工作进程已经停止。普通追问、八字前端及六爻首次解读的后续增量见下节；不能把界面恢复当成所有流程已交付。

## 普通追问请求记录与六爻恢复（2026-10-03）

- 新增 `chat_turn_requests`，按用户和请求编号保存状态、问题 hash、token、会话版本、完成消息编号及十分钟期限。`active_conversation_id` 唯一约束保证一个会话仅有一个有效在途位置，模型调用期间释放数据库锁。
- `/api/chat`、普通六爻追问及快捷分析接受可选 `request_key`。同编号/同问题在途请求返回 409；完成后直接回放持久回复，即使次数已用完也不会重新调用模型。编号绑定不同会话、不同内容或其他账号不能被复用。
- 完整问题、回复、一次旧配额与请求成功状态在同一事务提交；保存时核对 token、期限和最后一条消息编号。失败允许同编号重试；被接替、已过期或上下文变化的旧工作进程不能晚到后保存和扣次。正常失败/取消释放自己的预约，未知状态由期限恢复，不影响新 token。
- `GET /api/chat/requests/{request_key}` 仅查询当前账号的持久状态，不生成内容。六爻页面在发请求前保存编号与原问题草稿，刷新后先查询；在途时保持发送禁用，完成时读取对应消息，失败/到期后手动重试复用原编号。快捷问题手动重试保持原 label/prompt 操作，避免同编号切换接口或问题。
- 20 项新增后端隔离回归覆盖预约竞争、所有权、零额度回放、失败/过期重试、晚到 token、上下文变化、保存回滚、取消，以及八字/六爻实际流式服务对请求状态的提交。浏览器使用替代接口验证请求编号重用与在途禁止重发；尚未证明真实 MySQL 并发效果。
- 八字 `/panel`、`/chat` 已在下一增量接入请求编号，六爻首次解读也已在后续增量按卦象保护；普通追问的跨设备定位见后续增量。旧 `/chat` 普通自动开场的单入口生成保护已在后续增量补齐；个人报告与普通开场的跨入口竞争仍待统一。兼容的旧无编号追问接口没有本增量的完整重试幂等保证。M2/M4 保持未完成。
- staging 使用新版追问前先应用 `scripts/2026-10-03_chat_turn_requests.sql`，核对 `conversations.id` 为 signed INT、InnoDB。新表没有修改原表/旧报告；缺表的新编号请求返回 503，不静默降级成无保护生成。本次没有执行服务器迁移。

## 八字追问恢复与原始命盘（2026-10-03）

- `/panel` 与 `/chat` 共用 `useSavedBaziTurn`：发请求前按账号/会话保存编号、原问题、实际发送内容、显示文字和原任务事实；失败或停止移除临时问题与半截回复，保留完整原解读和可编辑草稿。刷新后未知结果先查询，不能直接重发。
- 恢复只查询持久请求状态与所属数据库会话。在途时禁用重发；完成时必须找到状态记录指定的回复编号，读取已保存结果；失败/到期后手动重试原问题复用原编号与原实际内容。用户改写的问题在旧请求可重试后使用新编号，恢复旧回答不会丢掉新草稿。快捷分析重试保留其显示文字、内部问题及原背景。
- `/panel` 和活动八字历史优先读取所属服务端会话，恢复该次保存的任务背景和命盘快照，不使用当前档案计算结果或全局浏览器缓存覆盖。另一账号无权读取的缓存会话不会显示；来源抽屉标明本次保存的命盘和排盘时间。
- 没有持久消息的兼容旧浏览器回答仍可阅读，明确说明来源限制并禁用直接追问，不伪造关联会话或将未保存回答当作服务端历史。

## 单问题权益规则（本地实现默认，发布前可配置）

- 新商品以配置标识为问题解读，价格来自商品表；不修改已有商品价格。
- 权益绑定用户和单一会话；八字/六爻各自使用会话，不因客户端传参跨会话使用。
- 期限与成功回复上限来自商品配置，并在购买时快照；界面在购买前明确展示。
- 期限从支付成功时开始，避免首次请求并发导致激活歧义。
- 支付通知幂等授予。只有服务端已确认支付的订单可获得权益。
- 生成失败不计成功回复；请求期间预留名额，阻止并发超额；重试有请求标识。
- 到期可查看历史；新权益可续问。旧次数保留，只有用户明确选择旧配额方式才消耗，不能静默双扣。
- 退款成功撤销该订单权益，不影响其他订单与旧配额；重复回调不重复处理。
- 本地测试以隔离数据库/替代支付提供方验证，不调用真实支付或改动线上配置。
